# Architecture

PTCGL Auto Battle Log has two parts that never talk to each other directly. They share files on
disk:

```
 Pokémon TCG Live (Unity/Mono)                         Windows tray app (PtcglAutoBattleLog.exe)
 ┌───────────────────────────────┐                     ┌──────────────────────────────────────────┐
 │ BepInEx 5 (winhttp.dll proxy) │                     │ installs / repairs BepInEx + the plugin   │
 │  └ PtcglAutoBattleLog.Plugin  │── *.txt, index.csv ─▶│ watches the logs folder → notifications  │
 │     reads the battle log from │── plugin-status.json▶│ shows status in the notification area    │
 │     the client at game over   │                     │ OTA: GitHub Releases → self-update        │
 └───────────────────────────────┘                     └──────────────────────────────────────────┘
          ▲  BepInEx\config\ptcgl.autobattlelog.cfg (logs folder)  ◀── tray "Change logs folder…"
```

* **Plugin** (`src/Plugin`, .NET Framework 4.7.2, BepInEx 5): runs inside the game. At the end
  of every match it calls the game's own battle-log exporter (the code behind the in-game Export
  button) and writes the text to disk. It does not simulate input or touch the UI.
* **Tray app** (`src/Tray`, .NET Framework 4.8 WinForms, single `.exe`): the installer, the
  repair daemon and the updater. The plugin DLL and the BepInEx zip are embedded in the exe as
  resources, so one file is all a player downloads.

Everything below is a contract: both sides, the tests and the release pipeline depend on it.

## Files and folders

### Per-user data: `%LOCALAPPDATA%\PtcglAutoBattleLog\`

| File | Written by | Purpose |
|---|---|---|
| `PtcglAutoBattleLog.exe` | tray installer / updater | the installed tray app (the only copy that runs) |
| `PtcglAutoBattleLog.exe.old` | updater | previous exe during a self-update; deleted on next start |
| `settings.json` | tray | tray settings (below) |
| `plugin-status.json` | plugin | heartbeat and last saved log (below) |
| `tray.log` (+ `tray.log.1`) | tray | diagnostic log, rotated at 512 KB |
| `updates\` | tray | downloaded update files |
| `tcgkb-connection.dat` | tray | the tcgkb connection, only once the player connects (see "tcgkb account"); in portable mode in the data folder like `settings.json` |
| `tcgkb-uploads.json` | tray | the match logs already sent to tcgkb, only once the player turns on automatic uploads (see "tcgkb account") |
| `pokematch-token.dat` | tray | the Pokematch API token, DPAPI-encrypted, only once the player sets one (see "Pokematch") |
| `pokematch-uploads.json` | tray | what was sent to Pokematch: per match, its key, Pokematch's id and the hash of what was sent (see "Pokematch") |

Leftovers of the 1.0 PowerShell installer (`payload\`, `watchdog.ps1`, `common.ps1`,
`uninstall.ps1`, `game-dir.txt`, `bepinex-installed-by-us.flag`, `watchdog.log`) are migrated and
removed by the tray installer: it reads `game-dir.txt` and the flag first, stops the PowerShell
watchdog and deletes `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\PTCGL Auto Battle Log.lnk`.

### Game folder (default `%USERPROFILE%\The Pokémon Company International\Pokémon Trading Card Game Live`)

| Path | Notes |
|---|---|
| `Pokemon TCG Live.exe` | identifies the game folder; process name `Pokemon TCG Live` |
| `winhttp.dll`, `doorstop_config.ini`, `.doorstop_version`, `changelog.txt`, `BepInEx\core\*` | BepInEx 5.4.23.3 win x64. Extracted only where missing, never overwritten. |
| `BepInEx\plugins\PtcglAutoBattleLog\PtcglAutoBattleLog.Plugin.dll` | the plugin. Replaced when its SHA-256 differs from the one embedded in the tray exe and the game is not running. 1.0 installed `PtcglAutoBattleLog.dll` in the same folder: delete it. |
| `BepInEx\config\ptcgl.autobattlelog.cfg` | BepInEx config of the plugin: `[General]` `OutputFolder = …`, `SaveManualExports = true`. Created by BepInEx on first game start; the tray may create or edit it. **The logs folder's single source of truth.** An empty `OutputFolder` (the plugin's default value) means the default folder `Documents\PTCGL Battle Logs`, resolved at runtime, so a profile path BepInEx cannot round-trip (e.g. containing `'`) is never written to the cfg. At startup the plugin uses the default folder (and logs a warning) when the value is one BepInEx garbled or would garble (`\'`, `"`, control characters, a single leading `\` left of a `\\server` path, or any value that changes in BepInEx's own write + read) or a folder that cannot be created; it writes `""` back for a garbled value and for the default folder spelled out. A relative value is relative to the game folder. The tray resolves the folder with the same rules (`GameInstall.ResolveLogsFolder`, so it never opens, creates, links or watches a garbled folder) and never writes a value the plugin would refuse, nor a folder an uninstall would delete (see "Install and uninstall"). Also `[Metadata]` `Mode` (see "Sealed logs"). Section and key names live in the plugin's `Core/PluginConfig.cs` and in `GameInstall`; `tests/TrayTests` checks that they agree, against the real BepInEx `ConfigFile`. |
| `BepInEx\LogOutput.log` | BepInEx log (plugin messages are prefixed `[Info   :PTCGL Auto Battle Log]`). |

### Logs folder (default `Documents\PTCGL Battle Logs`)

* One file per match: `yyyy-MM-dd HH.mm.ss - RESULT[ vs OPPONENT].txt` (local time of the match
  end), `RESULT` ∈ `VICTORY`, `DEFEAT`, `NO-RESULT`, `EXPORTED` (an Export click with no tracked
  match). Opponent sanitized for Windows file names (invalid characters and half surrogate pairs →
  `_`, trailing dots and spaces dropped, max 150 chars for the whole name); an opponent that
  sanitizes to nothing is left out (no dangling ` vs`). Duplicates get ` (2)`, ` (3)`… The tray
  parses every such name back (`LogFileName`); an opponent whose own name ends in ` (n)` is shown
  without it, because it reads like a duplicate's number.
  Content: exactly the text the in-game Export button produces, UTF-8 with BOM, followed in
  `Footer` seal mode (the default) by the seal block described in "Sealed logs"; in `Sidecar` and
  `Off` mode the `.txt` holds exactly the Export text.
  The plugin writes `<name>.tmp` and then renames it, and may overwrite the same file later with a
  longer read of the same match. If the result or opponent only becomes known after the first save
  (late winner, a reconnect), the file is moved to its corrected name (its `index.csv` row is updated),
  so a `NO-RESULT` file can be replaced by a `VICTORY`/`DEFEAT` one for the same match.
* `index.csv`: UTF-8 with BOM, CRLF, header
  `Date,Result,Opponent,Player,Deck,Duration (min),MatchId,File`, one row per match file.
* `decks\<sha256>.deck`: the player's own deck (`DeckList`, read from `deckInfo` while the match
  loads), one file per distinct deck, named by the SHA-256 of its bytes and named again by each
  log's seal (`deckSha256`). One line of ASCII JSON `{"v":1,"deckGuid","iterationCount","name",
  "deckDefinitionId","size","cards":{id:count}}`, card ids in ordinal order (docs/LOG-SEAL.md §2a).
  Written before the `.txt` unless the same bytes are already there; never moved or deleted; none
  in `Off` seal mode or when the client gives no cards.

### `plugin-status.json`

Written atomically (`.tmp` + replace) by the plugin when anything changes and at least every 30 s
while the game runs. UTF-8 without BOM. Dates are UTC, `yyyy-MM-ddTHH:mm:ssZ`; missing values are
`null`.

```json
{
  "pluginVersion": "1.1.0",
  "state": "ok",
  "message": "Watching for matches.",
  "logsFolder": "C:\\Users\\Ash\\Documents\\PTCGL Battle Logs",
  "savedThisSession": 2,
  "lastFile": "C:\\Users\\Ash\\Documents\\PTCGL Battle Logs\\2026-10-19 21.34.05 - VICTORY vs Gary.txt",
  "lastSavedUtc": "2026-10-19T21:34:05Z",
  "heartbeatUtc": "2026-10-19T21:35:00Z",
  "processId": 12345
}
```

`state`: `starting` (game classes not resolved yet), `ok`, `error` (`message` says why, e.g. the
game classes were not found after 90 s). The tray treats a heartbeat older than 90 s as "plugin not
running".

### `settings.json` (tray)

```json
{
  "gameDir": null,
  "bepInExInstalledByUs": false,
  "autoUpdate": true,
  "notifyOnSave": true,
  "lastUpdateCheckUtc": null,
  "skippedVersion": null,
  "disclaimerAccepted": 0,
  "pokematchAutoUpload": false,
  "pokematchSinceUtc": null,
  "updateChannel": "stable"
}
```

Unknown or missing fields fall back to these defaults; a corrupt file is kept as
`settings.json.corrupt` and replaced by defaults (and logged), never fatal.

## Tray app

### Command line

| Arguments | Behaviour |
|---|---|
| *(none)* | Not running from `%LOCALAPPDATA%\PtcglAutoBattleLog\PtcglAutoBattleLog.exe` → **install** (stop a running tray, copy self there, register, start the installed copy with `--first-run`, exit; see "Install and uninstall"), unless the installed exe is newer: then start (or show) that one and install nothing. Running from there (or in portable mode) → run the tray; if a tray is already running, tell it to show itself (balloon) and exit. |
| `--background` | Started by the `Run` key at logon: run the tray, silently if one is already running. Never installs (from outside the install folder in installed mode it exits) and never shows the disclaimer. |
| `--first-run` | Run the tray and show the welcome notification. |
| `--updated-from <version>` | Run the tray and show "Updated to vX". |
| `--portable` | Force portable mode (see below) even without the `portable.txt` marker. Combinable with the others. |
| `--uninstall [--quiet]` | Uninstall (Apps & Features calls this). Asks for confirmation unless `--quiet`. Stops a running tray first. Exit code 0 only when everything was removed; 1 (nothing changed) when the player cancels, when `--quiet` finds the game running (nobody can be asked to close it), or when a running tray does not exit; 1 when files are left in the game (see "Install and uninstall"). |

Single instance: named mutex `Local\PtcglAutoBattleLog-tray`. Inter-process signals: named events
`Local\PtcglAutoBattleLog-show` (another launch asks the running tray to show itself) and
`Local\PtcglAutoBattleLog-exit` (uninstaller / installer asks it to exit). A tray creates both
events right after it takes the mutex, before any dialog of its startup (consent, game folder
picker): a request that arrives meanwhile stays set and is honoured once the dialog closes
(startup stops there, or the tray exits as soon as it runs). The installer and uninstaller repeat
the exit request every 500 ms while they wait (up to 10 s) for the mutex. A mutex this process may
not open (a copy started with "Run as administrator" holds it) counts as "another copy is
running" and is reported as such, never as a crash.

### Windows integration (all per-user, no admin)

* Start with Windows: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value
  `PtcglAutoBattleLog` = `"<installed exe>" --background`.
* Apps & Features: `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\PtcglAutoBattleLog`
  (`DisplayName`, `DisplayVersion`, `Publisher`, `DisplayIcon`, `InstallLocation`,
  `UninstallString` = `"<installed exe>" --uninstall`, `QuietUninstallString`, `URLInfoAbout`,
  `NoModify`=1, `NoRepair`=1, `EstimatedSize`).
* Start menu shortcut `%APPDATA%\Microsoft\Windows\Start Menu\Programs\PTCGL Auto Battle Log.lnk`
  → installed exe. Desktop shortcut `PTCGL Battle Logs.lnk` → logs folder (re-pointed when the
  logs folder is changed from the menu, if it still exists).
* The installed copy has its Mark of the Web (`:Zone.Identifier`) removed, so the `Run` key never
  triggers an "Open File - Security Warning". A portable exe has it removed at every start once
  consent is given, and when "Start with Windows" is turned on.
* System DPI aware (`app.manifest` `<dpiAware>true</dpiAware>`, no `<dpiAwareness>`): WinForms on
  .NET Framework 4.8 handles per-monitor DPI only with an `app.config` opt-in, which a single exe
  cannot ship, so on a monitor with another scale Windows scales the windows (slightly blurred)
  instead of WinForms laying them out at the wrong size.

### Install and uninstall

* **Install** (installed mode, not running from the install folder): refused with a message when
  started with "Run as administrator" while UAC is on (an elevated tray's mutex would lock every
  later normal start out, and other credentials would install into another profile) → if the
  installed exe's `ProductVersion` is newer than this exe's version (`UpdateChecker.IsInstalledNewer`:
  build metadata ignored, a pre-release before its release), nothing is copied or registered: the
  running tray is asked to show itself, or the installed exe is started, and the player is told a
  newer version is installed (exit 0) → disclaimer → stop a running
  tray (exit event, then take the mutex, up to 10 s) → 1.0 migration → copy self to
  `PtcglAutoBattleLog.exe.new`, `SelfUpdate.Swap` it in → find the game (`GameLocator` with the
  registry `Uninstall` entries of HKCU, HKLM and HKLM's 32-bit view whose `DisplayName` contains
  `TCG Live` / `Trading Card Game Live`, and the running game's path; else a folder picker; Cancel
  installs anyway and the tray keeps looking once a minute) → `bepInExInstalledByUs` = the game had
  no BepInEx (or 1.0's flag names this folder) → `Repair` now if the game is closed → logs folder,
  `Run` key, Apps & Features, shortcuts → start the installed copy with `--first-run`.
* **Uninstall** (`--uninstall`; the menu's "Uninstall..." runs the installed exe with it; the order
  and the stops are `UninstallFlow`'s): confirm (unless `--quiet`) → wait for the game to be closed
  (Retry/Cancel; Cancel changes nothing; `--quiet` with the game running: exit 1, nothing changed) →
  stop the running tray (exit event + mutex; if it does not exit: say so unless quiet, exit 1,
  nothing changed, since that tray would put the mod back) → stop the 1.0 watchdog →
  `GameInstall.Uninstall(settings.bepInExInstalledByUs)`; if files are left in the game (in use,
  locked), stop: the `Run` value, the Apps & Features entry, the shortcuts, `settings.json`
  (`gameDir`, `bepInExInstalledByUs`) and the install folder stay, the player is told which files
  remain (unless quiet) and the exit code is 1, so the uninstall can simply be run again → remove
  the `Run` value (only if it starts this exe), the Apps & Features key and both shortcuts →
  delete `%LOCALAPPDATA%\PtcglAutoBattleLog\` **except `identity\`** (the plugin's signing key: the
  kept sealed logs name it, and a reinstall continues its chain). Files in use (the running exe) are
  deleted after exit by a hidden Windows PowerShell that waits for the uninstaller's process id. Its
  script is a constant and the folder and the names to keep (`|`-separated) travel in environment
  variables, so no path character can change what runs; it is not `-EncodedCommand` (antivirus
  heuristics flag hidden encoded commands).
  Battle logs are never deleted: "Change logs folder..." and `GameInstall.WriteOutputFolder` refuse
  a folder at or under the game's `BepInEx\` or the app's own folders (`%LOCALAPPDATA%\PtcglAutoBattleLog`,
  a portable copy's data folder and exe folder), and should the cfg still name one (edited by
  hand), `GameInstall.Uninstall` and the install-folder deletion keep the logs folder, its contents
  and the folders that lead to it (the plugin DLL is deleted regardless).
* **Portable** `--uninstall` / "Remove mod from game...": the same minus Apps & Features, shortcuts and
  folder deletion; `settings.gameDir` is forgotten, so running the copy again sets the game up afresh.

### Daemon loop

* Every 5 s: is the game running? Is the install complete (`GameInstall.Missing`)? If pieces are
  missing and the game is **not** running, wait 5 s more (an updater may still be writing), then
  `GameInstall.Repair`. If pieces are missing while the game **is** running, notify once: the game
  must be restarted after it finishes updating.
  A plugin that is only outdated (file present, hash differs) while the game runs is not reported:
  it is replaced once the game closes. A failed repair is retried after 30 s.
  While consent to the current `Disclaimer.Version` is pending (a tray started with `--background`
  or `--updated-from` after a bump), nothing is repaired or updated and no "restart" notice is shown;
  the status reads "Accept the updated disclaimer to keep the mod updated" (see "Disclaimer and
  consent").
  First install: when a `--first-run` (or first portable) tray starts with pieces missing while the
  game runs (the installer could not finish), the welcome says to close the game once to finish
  installing, the status reads "Close Pokémon TCG Live once to finish installing the mod" and the
  "a game update can remove it" notice is not shown for that episode (`DaemonMonitor.SetupPending`).
* Game running for 90 s without a fresh heartbeat → notify once per game session ("running without
  the mod"). Plugin `state` = `error` → notify once per game process.
* Logs folder watcher: a new `*.txt` (created or renamed into place) → notification
  "VICTORY vs Gary — battle log saved" (if `notifyOnSave`), debounced per file (1.5 s quiet, and the
  file must still exist, so a NO-RESULT file renamed to VICTORY within that time notifies once);
  overwrites of the same file do not notify again. It watches the running plugin's `logsFolder`
  while its heartbeat is fresh, else the cfg's folder; clicking the notification opens the file.
  A watcher follows the folder it was opened on, so on each report it is started afresh when the
  folder at that path is not the one it watches (`WatchedFolder`: gone, or made again with another
  creation time), e.g. after the folder was renamed in Explorer or deleted to the Recycle Bin.
* Tray icon: green dot = plugin heartbeat fresh (game running with the plugin), no dot = idle and
  healthy, amber = needs attention (repair pending, game running without plugin, game not found),
  red = error (plugin `error`, or a repair that failed).

### OTA updates

* Source: GitHub Releases of `BuildInfo.RepoOwner/BuildInfo.RepoName`.
  Manifest URL: `https://github.com/{owner}/{repo}/releases/latest/download/update.json`.
* Channels (`settings.json` `updateChannel`; anything but `beta` is stable). **Stable** reads the
  manifest URL above, so only the release GitHub marks latest. **Beta** reads
  `https://api.github.com/repos/{owner}/{repo}/releases?per_page=30` (at most 4 MB), drops drafts,
  takes the highest tag that is a SemVer version without `+build` and a safe name (pre-release or
  not), and reads `https://github.com/{owner}/{repo}/releases/download/{tag}/update.json`, whose
  `version` must equal the tag's. Versions compare as SemVer 2.0 (`1.3.2-beta.1` < `1.3.2-beta.2`
  < `1.3.2`). A beta build back on stable updates to the release of its number or a higher one.
* Checked 1 minute after start and then every 6 hours (and from the menu).
* Release assets: `PtcglAutoBattleLog.exe`, `PtcglAutoBattleLog-portable.zip`, `update.json`,
  `SHA256SUMS.txt` (hashes of the exe and the zip). `update.json` lists only the exe: installed and
  portable copies update from the same file.
* `release.yml` marks a release latest only when its version is at least the highest published
  `vX.Y.Z`: a new lower tag fails before building; a re-run of an older tag replaces its assets
  with `--latest=false` and skips the "latest serves this update.json" check. Release runs share one
  concurrency group. The SDK is the one `global.json` pins (`rollForward: disable`); the notes name
  the commit, SDK and Python that built the assets.

```json
{
  "version": "1.2.0",
  "tag": "v1.2.0",
  "releasedUtc": "2026-11-01T12:00:00Z",
  "notesUrl": "https://github.com/manucruzleiva/ptcgl-auto-battlelog/releases/tag/v1.2.0",
  "assets": [
    {
      "name": "PtcglAutoBattleLog.exe",
      "url": "https://github.com/manucruzleiva/ptcgl-auto-battlelog/releases/download/v1.2.0/PtcglAutoBattleLog.exe",
      "size": 812345,
      "sha256": "<64 lowercase hex chars>"
    }
  ]
}
```

* An update is applied only when **all** hold: `version` parses as `major.minor.patch` and is
  strictly greater than `BuildInfo.Version` (versions with a `-suffix` are pre-releases and are
  ignored on the stable channel; `+build` metadata is never offered); the asset URL is `https`, host exactly `github.com`, path starting
  `/{owner}/{repo}/releases/download/` (owner/repo compared case-insensitively); the downloaded
  byte count equals `size` and its SHA-256 equals `sha256`. Downloads follow GitHub's redirect to
  its asset CDN.
* Apply: download to `updates\PtcglAutoBattleLog-<version>.exe.partial`, verify, rename to `.exe`.
  Then rename the running exe to `PtcglAutoBattleLog.exe.old` (allowed on Windows), move the new one
  into place, start it with `--updated-from <old version>`, exit. The new instance waits up to 10 s
  for the old one's mutex, and deletes `.old` on start.
* The plugin is updated as a side effect: the new exe embeds the new plugin, and the daemon loop
  replaces the installed plugin once the game is closed.
* `autoUpdate` = false → only notify ("Update vX available", menu item to install), once per
  version; "Skip this version" stores `skippedVersion`, which automatic checks then ignore (a check
  from the menu does not). A failed check or download is logged and retried after 30 minutes;
  a download that fails verification is announced once per version.
* A portable copy started with `--portable` and no marker restarts with `--portable` too. An update
  that is ready while a dialog of the tray is open waits (retried 2 minutes later). Never during
  install or uninstall: those run in their own process, which stops the tray first.
* HTTP: `HttpClient`, `User-Agent: PtcglAutoBattleLog/<version>`, 30 s for the manifest, 10 minutes
  for the download (a stalled read is aborted), redirects must stay on `https`. TLS: Windows'
  default protocols (`SystemDefault`, TLS 1.2/1.3); TLS 1.2 is added when a machine policy pins an
  older explicit list.

## tcgkb account

Optional and off until the player connects: a tray that was never connected sends nothing to
tcgkb. The wire contract is [docs/TCGKB-API.md](TCGKB-API.md).

* **Connect to tcgkb...** asks first (what is sent, and when), then runs the OAuth device flow
  (`TcgkbConnection.ConnectAsync`): a code from `POST /api/device/code`, the browser opened on the
  `https://tcgkb.app/` page tcgkb names (any other address is refused), the code shown in a dialog,
  `POST /api/device/token` polled at tcgkb's interval until approved, declined, expired or
  cancelled. The app never sees the tcgkb password, and Google sign-in works too. The connection
  is saved only once `GET /api/ptcgl/accounts` has returned the user's name; otherwise the refresh
  token is revoked.
* `tcgkb-connection.dat` (in `AppPaths.Root`): `TcgkbTokens` as JSON, encrypted with DPAPI
  (`CurrentUser`, with app-specific entropy), written atomically. A file that does not decrypt or
  parse is deleted (= not connected). The access token is refreshed a minute before it expires and
  once more after a 401; a refused refresh (`invalid_grant`) deletes the file.
* **My PTCGL accounts...** lists the accounts `PtcglAccountScanner` finds in the logs folder (the
  plugin's `.txt` names only; their seal's `player.accountHash`, grouped, newest name, match count)
  next to the user's accounts on tcgkb, with **Claim** and **Release**. A claim asks first, then
  sends the account's newest 3 tracked matches (`matchId` set, result not `EXPORTED`, each file at
  most 1 MiB) exactly as on disk, `.seal` included. tcgkb verifies the seals; the tray does not.
* **Upload my matches automatically** (`Settings.TcgkbAutoUpload`, asked once after the first
  accounts dialog, off by default): `LogUploader.SyncAsync` lists the user's accounts on tcgkb,
  then sends `POST /api/ptcgl/logs` for each tracked match of those accounts not yet in
  `tcgkb-uploads.json` (`AppPaths.Root`; keys `matchId|accountHash|keyId`, accepted and rejected,
  and the `deckSha256` of decks tcgkb linked: each distinct deck file is sent once, as `deck`),
  newest first, at most 50 per run (another run follows at once when more are left). It runs at
  start, after each saved log and every 30 minutes; `not_claimed` leaves the log for later,
  `invalid_log` records it as rejected, any other error ends the run until the next one. One run
  at a time. **Upload matches now** runs it on demand; **Last upload** shows the newest result.
* **Disconnect** forgets the connection here, then revokes it on tcgkb (best effort: offline, the
  balloon says to remove the computer in the tcgkb profile).
* HTTP: its own `HttpClient`, `https://tcgkb.app` only, no redirects, no cookies, 30 s per request,
  responses capped at 1 MiB, `User-Agent` `PtcglAutoBattleLog/<version>`.
* The plugin is unchanged: it still makes no network connection.

## Pokematch

Optional and off until the player sets an API token: a tray without one sends nothing to
Pokematch. The wire contract is [docs/POKEMATCH-API.md](POKEMATCH-API.md).

* **Set API token...** checks the token with `GET /api/v1/me` (refused: say so, keep nothing;
  not reached: keep it anyway) after taking the token the player made on Pokematch's API Tokens page
  (`PokematchApi.CleanToken`: trimmed, a pasted `Bearer ` dropped, printable ASCII without spaces,
  at most 512 characters) and saves it in `pokematch-token.dat` (DPAPI `CurrentUser`, app-specific
  entropy, written atomically; a file that does not decrypt or parse is deleted). Then it offers to
  turn automatic uploads on.
* **Upload new battle logs automatically** asks first (what is sent), then sets
  `pokematchAutoUpload` and, the first time, `pokematchSinceUtc` = now: automatic runs only send
  matches that ended at or after it. "Upload past battle logs..." counts what Pokematch lacks in the
  whole logs folder, asks, and sends it.
* A run (`PokematchUploader.SyncAsync`, one at a time) takes the plugin's `.txt` files named
  `VICTORY` or `DEFEAT` (never `NO-RESULT` or `EXPORTED`), at most 1 MiB, not written in the last
  2 minutes (the plugin may still rewrite a log with a longer read or move it to its corrected name),
  oldest first, at most 25 per run (a manual run repeats until done). A match's key is
  `match:<the seal's matchId>`, else `file:<file name>`. What is sent is a Pokematch TCG log: the
  seal's deck (else "Unknown"), opponent deck "Unknown", Bo1 with one game of the result, the
  local date of the match end (seal, else file name), a note and the tag `ptcgl-auto-battle-log`.
  No names, account hashes or log text. `pokematch-uploads.json` keeps, per
  key, Pokematch's id and the SHA-256 of the JSON sent: an unchanged log is never sent again; a
  changed one is sent with `PUT /:id` (or `POST` again if it was refused before); a `PUT` answered
  404 marks the match deleted on Pokematch and it is never sent again.
* Answers: 401/403 stop the run and pause automatic uploads until a new token is set (balloon);
  network failures, timeouts (90 s: the host sleeps when idle), 408, 429 and 5xx stop the run and
  retry it 30 minutes later; any other refusal is recorded for that log (balloon once per kind of
  refusal) and the run goes on.
* When: 1 minute after start, 2 min 15 s after each "battle log saved", then every 10 minutes while
  automatic uploads are on and the current disclaimer is accepted. **Remove API token** deletes the
  file and turns automatic uploads off.
* HTTP: its own `HttpClient`, `https://pokematch-vslogger.onrender.com` only, no redirects, no
  cookies, responses capped at 1 MiB, `User-Agent` `PtcglAutoBattleLog/<version>`.

## Portable mode

Same exe, no installation. Portable mode is on when a file named `portable.txt` sits next to the
running exe, or with `--portable`.

* Release asset `PtcglAutoBattleLog-portable.zip` contains `PtcglAutoBattleLog\PtcglAutoBattleLog.exe`,
  `PtcglAutoBattleLog\portable.txt` (a short note explaining what the marker does), and the license
  texts of what the exe carries: `LICENSE.txt` (this project, MIT), `THIRD-PARTY-NOTICES.txt` and
  `licenses\LGPL-2.1.txt` (Unity Doorstop). Text entries have CRLF line endings; all entries are
  stored (not deflated), with the commit's time stamp, so the zip does not depend on a zlib build.
* Runs from wherever it is (the exe may have been renamed). Data lives in `<exe folder>\data\`:
  `settings.json`, `tray.log`, `updates\`. If that folder cannot be written (read-only media,
  Program Files), the app falls back to `%LOCALAPPDATA%\PtcglAutoBattleLog\portable-data\` and says so
  in the menu.
* `plugin-status.json` is still read from `%LOCALAPPDATA%\PtcglAutoBattleLog\` (the plugin does not
  know about portable mode).
* Never copies itself, never writes the Apps & Features key, never creates shortcuts. "Start with
  Windows" defaults to off; turning it on writes the same `Run` value pointing at the portable exe
  (with `--portable` appended when there is no marker file) and removes the exe's Mark of the Web,
  which every start after consent also does, so neither a start nor a logon shows "Open File -
  Security Warning".
* Still installs BepInEx + the plugin into the game folder (required to capture logs) and repairs
  them while it runs. "Uninstall..." becomes "Remove mod from game...", which removes the plugin (and
  BepInEx if this app installed it) and turns "Start with Windows" off; the user then deletes the
  folder.
* OTA updates swap the portable exe in place (`<exe>.old`), and restart it with the same mode.
* Shares the single-instance mutex and events with the installed app: only one of them runs at a
  time; a second launch asks the running one to show itself and exits.
* The 1.0 PowerShell cleanup runs in both modes.

## Disclaimer and consent

`DISCLAIMER.md` (repository root) is the single source of the disclaimer text. The tray exe embeds
it as the resource `DISCLAIMER.md`.

* Before the first install (installed mode) and before the first run (portable mode) the tray shows
  the disclaimer in a dialog with "I understand, install" / "I understand, continue" and "Cancel".
  Cancel exits without changing anything.
* Acceptance is stored as `settings.disclaimerAccepted` = `Disclaimer.Version` (an int, currently 3).
  The dialog is shown again only when `Disclaimer.Version` increases. `--background`,
  `--updated-from` and `--uninstall` never show it; a tray started that way after a bump shows a
  notification instead, whose click (or launching the app again, or "Repair now") opens the dialog.
  Until the first consent nothing is written: `tray.log` lines are held in memory and the portable
  `data\` folder is not created. After a bump, until the new version is accepted, nothing is
  written into the game: the daemon neither repairs nor updates the plugin (the new exe's plugin
  waits) and "Repair now" asks for consent first; the app itself keeps running and updating, and
  `tray.log` and `settings.json` keep being written in the folder the earlier consent allowed.
  Declining exits the tray, removes its `Run` value (so it does not come back at the next logon)
  and offers to remove the mod from the game (the `--uninstall` path, which asks once more).
* The README links to `DISCLAIMER.md` near the top and repeats its key points in the FAQ.

## Sealed logs (anti-tampering metadata)

Every saved battle log carries a signed metadata block ("seal") so a future online leaderboard can
detect logs that were edited or fabricated. Full specification, threat model and server-side
verification guidance: `docs/LOG-SEAL.md`. Summary of the contract:

* **Identity**: on first use the plugin creates an RSA-2048 key pair per Windows user:
  `%LOCALAPPDATA%\PtcglAutoBattleLog\identity\signing-key.xml` (private, `RSA.ToXmlString(true)`),
  plus `identity\chain.json` `{"seq":N,"last":"<hex>","keyId":"<keyId>"}` (`{"seq":0,"last":null,...}`
  for a new key before its first seal; a file without `keyId` is read as the current key's). Key
  generation runs off Unity's main thread.
  `keyId` = RFC 7638 JWK thumbprint (SHA-256, base64url without padding) of the public key.
  An unusable key file (also: under 2048 or over 4096 bits, exponent not 65537) is kept as
  `signing-key.xml.corrupt` and replaced (new key, new chain). At every load `chain.json` is
  checked against the logs folder: a missing, corrupt or other key's `chain.json` is rebuilt from
  the newest seal of the key there; a present one moves up to a newer seal of the key written since
  (from 10 minutes before `chain.json`'s own write time: a higher `seq`, or the same `seq` with
  another chain hash). Only seals whose public key is the key and whose canonical signature
  verifies count. A failed `chain.json` write is retried with the plugin's 5 s heartbeat, at the
  next seal and when the plugin shuts down.
* **Mode**: BepInEx cfg `[Metadata]` `Mode = Footer | Sidecar | Off` (default `Footer`).
  * `Footer`: the seal is appended to the `.txt`, after the exact Export text, as:

    ```
    <exact Export text>\n
    \n
    -----BEGIN PTCGL-ABL SEAL v2-----\n
    <metadata JSON, one line>\n
    <signature, standard base64, one line>\n
    -----END PTCGL-ABL SEAL v2-----\n
    ```

    The log is everything before the **last** occurrence of `\n\n-----BEGIN PTCGL-ABL SEAL v`
    (after removing a leading UTF-8 BOM); the BEGIN line's number is the version (v1 seals of
    earlier builds stay valid and are read by the chain repair, `SealSummary` and the verifier).
  * `Sidecar`: the `.txt` holds only the Export text; the same block (from `-----BEGIN` to the end)
    is written to `<same name>.seal` next to it (the `.txt` name with the extension `.seal`;
    ASCII, no BOM). A rewrite in `Footer` or `Off` mode deletes the file's stale `.seal`.
  * `Off`: no seal, the chain does not advance.
* **Metadata JSON** — one line, no whitespace, pure ASCII (`\uxxxx` from U+007F up), keys in
  exactly this order, written by the plugin's JSON writer; verifiers must check the signature over
  the exact bytes and must not re-serialize:
  `v` (2), `app` ("PTCGL Auto Battle Log"), `pluginVersion`, `gameVersion` (Unity
  `Application.version` or null), `capture` (`"auto"`: the plugin's own read; `"export"`: the sealed
  text came from the player's Export click, always so for `EXPORTED`), `matchId` (or null),
  `startedUtc`, `endedUtc`, `result` (`VICTORY|DEFEAT|NO-RESULT|EXPORTED`), `winner` (1|2|null),
  `mySeat` (1|2|null), `player` {`name`, `accountHash`}, `opponent` {`name`, `accountHash`}, `deck`,
  `deckSha256` (lowercase hex SHA-256 of the `decks\<hash>.deck` file, or null; absent in v1), `logSha256` (lowercase hex SHA-256 of the UTF-8 bytes of the log), `logChars` (UTF-16 length of
  the log), `sealedUtc`, `seq`, `prev` (hex chain hash of the previous seal, null for seq 1),
  `keyId`, `publicKey` {`kty`:"RSA", `n`, `e`} (base64url, no padding).
  `accountHash` = lowercase hex SHA-256 of the UTF-8 string `"ptcgl-abl:v1:" + accountId` (null when
  unknown): both players' seals of one match name the same accounts without exposing raw ids.
* **Signature**: RSASSA-PKCS1-v1_5 with SHA-256 over the UTF-8 bytes of the JSON line.
* **Chain hash** of a seal: lowercase hex SHA-256 of `<JSON line bytes> + "\n" + <signature line
  bytes>`. `seq` starts at 1. Re-sealing a file (a longer read of the same match, or the file moved to
  its corrected name) keeps its `seq` and `prev` when it is still the latest seal; otherwise it takes
  the next `seq` (the verifier then reports a gap, which is expected and explained in LOG-SEAL.md).
  A move whose old file cannot be moved (locked) also takes the next `seq`, so two files never claim
  one place. `chain.json` is updated atomically after the file is written.
* If signing is unavailable (key cannot be created or used), the log is saved **without** a seal, a
  warning is logged and `plugin-status.json` `message` says so. A log is never lost because of the seal.
* **Verifier**: `tools/verify_log.py` (python3, stdlib only). `verify_log.py FILE...` checks each file
  (footer or sidecar), `verify_log.py --chain DIR` also checks per-`keyId` chain continuity,
  `--key KEYID` (repeatable) also rejects valid seals made with any other key. Exit codes:
  0 all valid, 1 something invalid, 2 usage error (also: a FILE or DIR that does not exist, a
  `--key` that is not a keyId). Output: one line per file (`OK` lines name the full `keyId`) plus a
  summary; text from files and file names is printed with control and format characters escaped
  (`\uXXXX`). Forks and broken `prev` links are errors, gaps are warnings; an unsealed FILE given
  by name is invalid, unsealed logs found by `--chain` are listed but are not errors (pre-1.1 logs,
  `Mode = Off`). Before any RSA arithmetic it rejects a `.txt` over 16 MiB, a seal block over
  16 KiB, a modulus outside 2048-4096 bits and an exponent other than 65537; the signature line
  must be canonical base64 (re-encoding the decoded bytes gives the line back), because the chain
  hash covers its text. `--self-test` checks the verifier itself.
* **Cross-language test**: `tests/CoreTests` writes sample sealed logs (a chain of at least 3 footer
  seals and 1 sidecar) into the folder named by the env var `PTCGL_SEAL_SAMPLES` when it is set;
  `build.sh` runs the verifier on them (must pass) and on a tampered copy (must fail).
